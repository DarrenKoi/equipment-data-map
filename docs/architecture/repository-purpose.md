# Equipment Data Map 저장소의 목적

> 이 문서는 저장소의 목적을 빠르게 이해하기 위한 개요다. 실행 규칙과 데이터 계약의 기준은 [Equipment Data Map 아키텍처](equipment-data-map.md)다.

## 한 문장으로 설명하면

FAB 장비의 파일 저장소를 읽기 전용으로 안전하게 탐색하고, 반복되는 파일을 묶어 최소한의 대표 샘플만 분석함으로써 근거를 추적할 수 있는 **장비 데이터 지도**를 만드는 저장소다.

목표는 백업이 아니라 이해다. 모든 파일을 복제하지 않고 다음 질문에 답할 수 있는 구조화된 지도를 만든다.

- 어떤 경로에 어떤 성격의 파일이 있는가?
- 파일명, 디렉터리와 생성 시각에는 어떤 규칙이 있는가?
- 파일 안에는 어떤 필드와 데이터가 있으며 무엇에 쓰이는가?
- 같은 형식의 파일은 얼마나 자주, 얼마나 많이 생성되는가?
- 파일군은 서로 어떤 근거로 연결되는가?
- 해석하지 못한 파일은 무엇이며, 그 이유는 무엇인가?

## 백업이 아니라 지도

장비 저장소의 모든 데이터를 가져오는 방식은 장비 부하, 보안, 저장 비용과 검토 가능성 측면에서 적합하지 않다. 이 저장소는 다음 순서로 필요한 정보만 다룬다.

1. **Inventory** — 파일 내용을 받기 전에 경로, 크기, 수정 시각 등 메타데이터를 수집한다.
2. **Grouping** — 내용을 받지 않고 경로, 파일명 규칙, 확장자만으로 반복되는 파일을 묶는다.
3. **Sampling** — 반복 파일군에서는 최근 파일 3개와 무작위 2개, 나머지 묶음에서는 무작위 최대 3개만 대표 샘플로 고른다.
4. **Extraction** — 텍스트, 표, 설정, 로그와 바이너리에서 관측 가능한 구조를 결정론적으로 추출한다.
5. **Local LLM Analysis** — 회사망 내부의 로컬 LLM이 대표 샘플의 의미와 운영 용도를 제한된 형식으로 추론한다.
6. **Data Map** — 관측 사실과 추론을 구분하고 근거와 미해결 항목을 함께 기록한 canonical JSON을 만든다.

수집 범위와 안전 판단은 코드가 담당한다. LLM은 파일 선택이나 예산을 결정하지 않으며, 이미 선택된 대표 샘플의 의미 해석만 맡는다.

## 기준 데이터와 파생 산출물

`data-map/`이 기준 데이터 세트다. 여기에는 장비, 경로, 파일군, 관측 사실, 추론, 미해결 항목과 근거가 구조화되어 저장된다.

검토된 지도에서는 다음 산출물을 다시 만들 수 있다.

- **Wiki** — 엔지니어와 LLM이 장비 데이터 구조와 운영 맥락을 읽고 검토하는 Obsidian 호환 문서
- **Graph JSONL** — 파일군 사이의 관측된 구조·내용 관계와 근거

Wiki와 Graph는 별도의 진실 원천이 아니다. 모두 canonical data map에서 재생성할 수 있는 파생 산출물이다.

## 지켜야 할 원칙

- **읽기 전용:** 장비에서 파일을 생성·수정·삭제하거나 이름을 바꾸지 않는다.
- **목록 우선:** 전체 파일을 복제하기 전에 메타데이터 목록부터 수집한다.
- **대표 샘플:** 파일군마다 승인된 소수의 샘플만 분석한다.
- **명시적인 예산:** 허용 경로, 연결 수, 요청 속도, 다운로드 수와 용량, 실행 시간을 제한한다.
- **근거 보존:** 모든 해석에 장비, 경로, 샘플, 추출 방식과 신뢰도를 연결한다.
- **불확실성 기록:** 암호화·손상·미지원 파일도 누락하지 않고 `unreadable` 또는 미해결 상태로 남긴다.
- **재개 가능:** 대화 기억이 아니라 체크포인트와 감사 기록을 기준으로 중단 지점부터 이어서 실행한다.
- **회사망 내부 처리:** 원본 파일과 분석 결과를 회사망 밖으로 반출하지 않는다.

## Rollout 방식

실제 장비에 바로 적용하지 않는다. 한 엔지니어가 같은 rollout ID를 유지하면서 각 단계의 실행 전 계획과 실행 후 결과를 확인한다.

1. **1단계 — 가짜 장비 검증:** 로컬 가짜 FTP에서 LLM 없이 수집·분류·샘플링과 지도 생성을 검증한다.
2. **2단계 — 로컬 LLM 연결:** 측정 데이터와 로그 표본으로 필드별 구조화 해석과 검증 절차를 확인한다.
3. **3단계 — 장비 1대 시범 운영:** 좁은 허용 루트와 작은 예산으로 승인된 장비를 읽기 전용으로 탐색한다.
4. **4단계 — 파생 산출물 생성:** 검토된 지도에서 Wiki와 Graph를 생성한다.
5. **5단계 — 장비 종류 확장:** 프로필과 기존 extractor 매핑을 검증해 다음 장비 유형으로 확장한다.

이 5단계 rollout은 한 번의 분석 실행 안에서 반복되는 6단계 런타임 파이프라인과 서로 다른 개념이다.

## 저장소가 제공하려는 것

이 저장소의 최종 산출물은 단순한 수집기가 아니다. 엔지니어가 장시간의 탐색을 안전하게 감독할 수 있도록 다음 요소를 하나의 실행 계약으로 묶는다.

- 재현 가능한 CLI와 안전장치
- 중단 후 재개할 수 있는 체크포인트와 감사 기록
- 단계별 실행 절차와 운영자 승인 지점
- 가짜 FTP 기반의 검증 시나리오
- 회사 내부 에이전트가 사용할 수 있는 이식 가능한 스킬
- 사람이 검토할 수 있는 지도, Wiki와 Graph 산출물

세부 동작, 상태 전이, 데이터 형식과 완료 기준은 [Equipment Data Map 아키텍처](equipment-data-map.md)를 따른다.
