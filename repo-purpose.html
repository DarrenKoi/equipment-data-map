01 / PURPOSE

백업이 아니라,
이해를 위한 지도

모든 파일을 가져오는 것이 목표가 아닙니다. 목록과 규칙을 먼저 파악하고, 파일군마다 필요한 대표 샘플만 확인해 장비 데이터의 구조와 의미를 설명합니다.

WHERE

어떤 경로에 어떤 성격의 파일이 있으며, 파일명과 디렉터리에는 어떤 규칙이 있는가?

WHAT

파일 안에는 어떤 필드와 데이터가 있으며, 각 파일군은 로그·FDC·설정·측정 결과 중 무엇인가?

WHEN

같은 형식의 파일은 얼마나 자주 생성되고, 시간에 따라 어떻게 달라지는가?

WHY

운영과 장애 분석에서 어떤 근거 파일을 찾아야 하며, 파일군은 어떻게 연결되는가?

Runtime pipeline

규칙은 코드로,
해석은 필요한 곳에만

결정론적인 도구가 수집 범위와 사실을 먼저 고정하고, 회사 내부의 로컬 LLM은 대표 샘플의 의미를 제한적으로 해석합니다.

Inventory

내용을 받기 전에 경로, 크기, 수정 시각 등 메타데이터부터 수집합니다.

Grouping

경로, 파일명, 확장자, 크기와 제한된 형식 특징으로 반복되는 파일을 묶습니다.

Sampling

각 파일군에서 오래된 파일, 최신 파일, 중앙값 파일, 예외 파일 등 소수의 대표 샘플만 고릅니다.

Extraction

텍스트, 표, 설정, 로그와 바이너리의 관측 가능한 구조를 결정론적으로 추출합니다.

Local LLM

회사망 안에서 파일의 의미, 필드, 생성 주기와 운영 용도를 제한된 형식으로 추론합니다.

Data Map

관측 사실과 추론을 구분한 canonical JSON으로 근거와 미해결 항목까지 기록합니다.

Map, not backup

전체 파일을 복제하지 않습니다. 목록을 먼저 만들고, 승인된 범위와 예산 안에서 대표 샘플만 분석합니다.

One source, many views

하나의 기준 지도에서
필요한 보기를 만듭니다

data-map/이 기준 데이터 세트입니다. Wiki, Graph와 RAG는 서로 다른 진실이 아니라, 검토된 지도에서 언제든 다시 만들 수 있는 파생 산출물입니다.

JSON

Canonical Data Map

장비, 경로, 파일군, 관측 사실, 추론, 미해결 항목과 근거를 구조화합니다.

MD

Wiki

엔지니어가 장비 데이터 구조와 운영 맥락을 읽고 검토할 수 있는 문서입니다.

G

Graph JSONL

파일군 사이의 관측된 구조·내용 관계를 근거와 함께 연결합니다.

R

RAG JSONL

원문 전체가 아니라 출처를 추적할 수 있는 제한된 claim 단위로 검색을 지원합니다.

Fail-closed by design

안전은 설명이 아니라 실행 조건입니다

모델의 판단에 안전을 맡기지 않습니다. 스크립트와 CLI가 허용 범위, 상태 전이, 예산과 승인을 검사하고 조건이 맞지 않으면 닫힌 상태로 멈춥니다.

✓

읽기 전용 접근

장비에서 파일을 생성·수정·삭제하거나 이름을 바꾸는 동작은 허용하지 않습니다.

✓

명시적인 범위와 예산

허용 경로, 연결 수, 요청 속도, 다운로드 수와 용량, 실행 시간을 계획에 고정합니다.

✓

근거와 불확실성 보존

관측 사실과 LLM 추론을 구분하고, 암호화·손상·미지원 파일도 누락하지 않고 사유를 남깁니다.

✓

중단 후 재개

체크포인트와 감사 기록을 기준으로 이어서 실행하며, 대화의 기억을 상태로 사용하지 않습니다.

✓

회사망 내부 처리

원본 파일과 분석 결과는 회사망 밖으로 반출하지 않으며, 승인된 내부 LLM만 사용합니다.

Human-gated rollout

가짜 장비에서 시작해
한 단계씩 검증합니다

각 단계마다 엔지니어가 실행 전 계획과 실행 후 결과를 확인해야 다음 단계로 넘어갑니다.

1단계

가짜 장비 검증

로컬 가짜 FTP에서 LLM 없이 수집·분류·샘플링과 지도 생성을 검증합니다.

2단계

로컬 LLM 연결

측정 데이터와 로그 표본으로 필드별 구조화 해석과 검증 절차를 확인합니다.

3단계

장비 1대 시범 운영

좁은 허용 루트와 작은 예산으로 승인된 장비를 읽기 전용으로 탐색합니다.

4단계

파생 산출물 생성

검토된 지도에서 Wiki, Graph와 RAG를 생성하고 모든 답변에 근거를 연결합니다.

5단계

장비 종류 확장

프로필과 기존 extractor 매핑을 검증해 다음 장비 유형으로 확장합니다.

두 종류의 단계를 구분합니다. 위 5단계는 운영 승인 단위인 rollout이고, 앞의 Inventory부터 Data Map까지 6단계는 한 번의 분석 실행 안에서 반복되는 런타임 파이프라인입니다.
