# 6. 사이트 차이를 데이터로 빼기 — 보편화

키우는 성질: **보편화** · office 데이터: 필요 (장비 2종 이상)

## 왜

여기까지 오면 장비 한 대에 대해 잘 도는 agent 가 있다. "보편적으로 활용"
은 그다음 질문이다 — **두 번째 장비에 붙일 때 코드를 고치는가, 파일을
고치는가?**

코드를 고쳐야 한다면 보편적이지 않다. 세 번째 장비에서 또 고치고, 그때쯤
첫 번째 장비가 깨진다.

## 개념

**첫 번째 구현은 일반화하지 마라. 두 번째가 나타나면 그때 차이를 뺀다.**

두 장비를 나란히 놓고 다른 점을 적는다. 각 차이는 셋 중 하나다.

| 차이의 종류 | 어디로 가는가 | 예 |
|---|---|---|
| 값이 다르다 | `equipment.toml` | host, roots, 예산 |
| 규칙이 다르다 | profile 파일 (데이터) | 파일명 패턴, 인코딩, 확장자별 의미 |
| 동작이 다르다 | 코드 (동사 안의 분기) | 서버가 SIZE 를 지원하지 않음 |

세 번째 칸은 **가능한 한 비워라.** 코드 분기가 하나 생길 때마다
장비 수 × 분기 수만큼 테스트해야 할 조합이 늘어난다. 값이나 규칙으로
표현할 수 있으면 그렇게 한다.

profile 은 별도 설계가 아니라 **`equipment.toml` 에서 사이트마다 반복되는
부분을 뽑아낸 파일** 이다. 처음부터 만들지 말고, 두 번째 `equipment.toml`
을 쓰면서 복사-붙여넣기 하게 되는 덩어리가 곧 profile 이다.

## 실습

1. 두 번째 장비(또는 성격이 다른 fake 트리)로 `equipment.toml` 을 하나 더
   쓴다. **코드는 손대지 않는다.**
2. 돌린다. 어디서 깨지는지 적는다. 깨진 것마다 위 표의 어느 칸인지 판정한다.
3. "값" 이면 config 로, "규칙" 이면 profile 로 뺀다. "동작" 이면 — 정말
   동작인지 한 번 더 의심한다. 대개 규칙이다.
4. 두 장비를 같은 코드로 돌린다. `out/tool-a/`, `out/tool-b/` 둘 다 나온다.

**회귀 확인**: 두 번째 장비를 붙인 뒤 첫 번째 장비를 다시 돌려 결과가
같은지 `diff -r` 한다. 이게 다르면 일반화가 아니라 이사(移徙)를 한 것이다.

## 통과 기준

`git diff` 상 코드 변경 없이 (혹은 profile 로 설명되는 변경만으로) 두 장비가
같은 CLI 로 돌고, 첫 장비의 출력이 회귀하지 않는다.

## 다음

여기까지가 "FAB 장비 파일 저장소" 범위다. 그 바깥(다른 회사, 다른 프로토콜)
으로 넓히려면 Source 어댑터 층이 필요하고, 그건 `spec.md` §4 의 seam 이다.
**세 번째 종류의 저장소가 실제로 나타나기 전에는 만들지 마라.**

## 이 단계에서 배워 갈 것

보편성은 설계로 얻는 게 아니라 **두 번째 사례로 얻는다.** 사례 하나로
일반화한 추상은 거의 항상 틀린 축으로 일반화돼 있다.
