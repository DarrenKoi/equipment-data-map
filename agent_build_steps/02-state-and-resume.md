# 2. 상태를 파일로 내보내고 재개하기

키우는 성질: **관측** · office 데이터: 불필요

## 왜

지금 `spike.py` 가 남기는 상태는 마지막 줄 JSON 하나다. 중간에 죽으면
(네트워크 끊김, `max_dirs` 도달, Ctrl-C) 다음 실행은 처음부터 다시 걷는다.
장비 한 대에 디렉터리 500개면 참을 만하지만, agent 가 여러 세션에 걸쳐
돌리기 시작하면 못 참는다.

더 중요한 이유: **모델은 자기가 뭘 했는지 기억하지 못한다.** 세션이 끊기면
컨텍스트도 끊긴다. 그러니 "어디까지 했나" 는 모델의 기억이 아니라 파일이어야
한다. 이게 `CLAUDE.md` 의 `audit.jsonl` 불변식이 말하는 바다.

## 개념

**append-only ledger**: 한 줄 = 한 사건, 고쳐 쓰지 않고 덧붙이기만 한다.
현재 상태는 저장하는 게 아니라 **줄을 접어서 계산한다(derive)**.

```
{"t":"2026-09-13T01:02:03Z","ev":"dir_done","path":"/log/a","files":12,"bytes":40960}
{"t":"...","ev":"dir_failed","path":"/log/b","error":"550"}
{"t":"...","ev":"budget_stop","bytes":200000000}
```

왜 `state.json` 을 고쳐 쓰지 않나:

- 쓰는 도중에 죽으면 `state.json` 은 반쯤 망가지지만 jsonl 은 마지막 줄만 버리면 된다
- 두 프로세스가 동시에 붙어도 append 는 섞이지 않는다 (한 줄이 원자적인 크기라면)
- "왜 이렇게 됐나" 를 나중에 추적할 수 있다. 상태 스냅샷에는 없는 정보다

대신 대가가 있다: 상태를 알려면 파일을 처음부터 읽어야 한다.
`ponytail:` 주석으로 천장을 적어 둬라 — 수십만 줄이 되면 스냅샷을 곁들인다.

## 실습

`spike.py` 에 두 가지를 더한다.

1. 디렉터리 하나를 끝낼 때마다 `out/<name>/audit.jsonl` 에 한 줄 append.
   `stats` 를 갱신하는 바로 그 자리다.
2. 시작할 때 `audit.jsonl` 이 있으면 읽어서 `dir_done` 인 경로를 `seen` 에
   미리 넣고, `stats` 를 거기서 복원한다. 큐는 roots 부터 다시 시작해도 된다 —
   `seen` 이 있으면 걷기는 자연히 건너뛴다.

**끊고 재개해 보기**:

```
# fake 트리에서 max_dirs 를 2 로 낮춰 한 번 돌린다
python spike.py equipment.toml          # dirs=2, 큐 남음
wc -l out/tool-a/audit.jsonl            # 2
# max_dirs 를 10 으로 올려 다시 돌린다
python spike.py equipment.toml          # 이미 본 2개는 다시 안 걷는다
```

두 번째 실행의 `dirs` 가 8 이고 (10 이 아니라) markdown 파일 총수가 10 이면
재개가 된 것이다.

여기서 **판정 boolean 이 깨진다.** `md_per_dir` 은 `stats["md"] == stats["dirs"]`
인데, 재개하면 이번 실행에서 쓴 md 는 8개다. 판정을 "이번 실행" 이 아니라
"누적" 기준으로 다시 정의해야 한다. 이게 이 단계의 진짜 교훈이다 —
**재개를 넣으면 완료 판정도 같이 바뀐다.**

## 통과 기준

끊었다 재개한 뒤의 markdown 개수와 `audit.jsonl` 의 `dir_done` 줄 수가 같고,
세 boolean 이 모두 참이다.

## 이 단계에서 배워 갈 것

재개 가능한 상태 = agent 가 여러 세션을 살아남는 유일한 방법. 그리고 상태를
바꾸면 완료 판정을 반드시 다시 본다.
